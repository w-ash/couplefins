# v1.9.2 — Three-Block System Prompt + Current View

Status: Planned
Effort: S
Depends on: v1.9.0 (the `page` request signal)
Series overview: [v1.9.x — Context Engineering](v1.9.x-context-engineering.md)

## Goal

Split the single cached system block into mixd's three-block shape:

- **Block A — primer** (cached, the only system breakpoint): everything
  static — identity minus names/date, voice examples/rules, scope,
  tool_habits, untrusted_content, domain_model, response_format,
  mutation_rules. `functools.lru_cache` keyed by voice name; the
  `get_voice` fallback (unknown → "standard") must resolve *before* the
  cache key so an invalid name can't poison the keyspace. Zero per-request
  values — byte-stable across users and days.
- **Block B — volatile context** (uncached, trailing): person/partner
  names, today's date, category groups (couple-editable strings leave the
  cached block).
- **Block C — `<current_view>`** (uncached, only when present): "The user
  is currently on the {page} page — prefer it as the default subject when
  the request is ambiguous." Emitted only when `page ∈ _CANONICAL_PAGES`
  (reuse the registry set — never reflect arbitrary client strings into the
  prompt).

**Honest sizing note:** the cache win is marginal for a two-user app (date
rollover is rare mid-conversation; per-person `chat_voice` mostly forfeits
cross-partner primer sharing). The real value is Block C's grounding of
ambiguous questions and structural convergence with mixd for future
backports.

## Tasks

- [ ] **Prompt split** — `system_prompt.py`: `_primer(voice_name)` (cached,
  breakpoint) + `_user_context_block(person, partner, today, groups)` +
  `_current_view_block(page)`; `build_system_prompt` gains `page` and
  returns the block list with the breakpoint on the primer only. Trailing
  blocks must never carry `cache_control` (the 4-breakpoint budget is spent).
- [ ] **Threading** — `routes/chat.py` passes `body.page` into
  `build_system_prompt`.
- [ ] **Tests** — `test_system_prompt.py`: breakpoint on first block only;
  primer byte-stable across users/days; names/date/groups asserted in
  Block B; Block C presence/absence (valid page, unknown page, None);
  token-floor guard (tools + primer prefix comfortably over the 4096 Opus
  4.8 cache-activation floor). Integration: update the two `client_date`
  tests (date now in Block B); add a page → Block C assertion.
