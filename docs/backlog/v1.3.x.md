# v1.3.x: Per-Month Budget Model

For strategic overview, see the [planning overview](README.md).

## Scope Design Decisions

**Household vs personal budgets are completely separate views.** The scope toggle on the Budget page switches between two independent budget sets — no cross-visibility. Household scope shows household budgets only; personal scope shows personal budgets only.

**`include_personal` affects the combined budget target.** When a category has `include_personal=true`, personal spending counts against the household budget. The budget amount should be set knowing this — the average spending hint includes personal transactions (e.g., "Avg: $800 (incl. personal)") so the user sets an appropriate target.

**Copy from previous month copies household + the caller's personal budgets.** One click copies all household budgets (shared) plus the current user's personal budgets from the most recent prior month with budgets (not necessarily the immediately previous month — handles skipped months). The partner copies their own personal budgets separately on their device.

**Budget ownership.** All budget mutation endpoints (`POST`, `PUT`, `DELETE`, `POST /budgets/copy`) derive `person_id` from the authenticated user's JWT — never accepted from the request body. Household budgets use `person_id=NULL` with a partial unique index (see migration spec).

**`null` vs `0` for missing budgets.** A month with no budget record returns `null` (not `0`). `null` means "no budget set" — no overlay line on charts, $0 contribution to YTD. `0` means "explicitly budgeted at zero" — line shown at baseline. This distinction must be maintained through the full stack: domain entities, API responses, and frontend rendering.

**Deleting a budget returns the group to "no budget set."** Delete produces `null` (no record), not `0`. No overlay line on charts, no YTD contribution. This is distinct from setting a budget to $0, which is an explicit "we're spending nothing here" signal.

**`get_by_year` returns sparse results.** The repository returns only months where a budget record exists — no gap-filling, no placeholder rows. Callers sum returned amounts directly. A year with 3 budgeted months returns 3 records, not 12.

### v1.3.0: Per-Month Budget Model
**Goal**: Replace the cascading effective-date budget model with simple per-month budgets. Each month has its own independent budget amounts per category group.
**Status**: Completed (2026-04-04)
**Context**: The current model stores budgets with an `effective_from` date — a budget cascades forward indefinitely until a newer one takes effect. This is correct but unintuitive. Users think "I want to budget $X for this category this month," not "I want this budget to take effect on this date and cascade." Monarch Money and YNAB both use per-month amounts. The couple reviews budgets monthly; the model should match that cadence. Deleting a budget erases history, there's no way to "stop" budgeting a category, and the effective date field had to be hidden because it confused users.
**What this unlocks**: Simpler mental model — each month is independent. Delete means delete (just this month). No effective dates. YTD is the honest sum of months where a budget was set.
