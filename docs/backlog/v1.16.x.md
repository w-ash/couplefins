### v1.16.0: Slim month-status endpoint for the Transactions header card
**Goal**: The Transactions header card stops polling the full settle-up payload for one status line.
**Status**: Planned
**Context**: `useSettleUpForMonth` in `web/src/components/TransactionsHeaderCards.tsx` refetches `GET /settle-up` every 5s. Each poll runs ~8 DB queries server-side (all-time transactions, settlements, portions, link enrichment, month reconcile, uploads, period status) and ships the whole ledger + settlement history to render a single month's balance line. Flagged in the v1.11.0 efficiency review; deferred because 5s polling on together-session pages is the deliberate SSE fallback, so the fix is a slimmer payload, not dropped polling.

- [ ] **Month-status endpoint (or slim response shape)**
    - Effort: S
    - What: A lightweight read for one month's `balance`/`charged`/`paid`/`status` (either a dedicated endpoint or a `?slim=` variant reusing the portion math), consumed by `TransactionsHeaderCards`; the full settle-up fetch stays on the Settle Up page only. Polling cadence unchanged.
    - Why: The hottest polled path should not pay for the whole ledger to draw one card.
    - Dependencies: v1.11.0 (precomputed settle-up API)
    - Status: Not Started
    - Notes: Keep the response a strict subset of `months[]`'s entry shape so the card renders the same fields either way.

### v1.16.1: Structured warnings
**Goal**: Warning copy is composed in the frontend; use cases return data, not sentences.
**Status**: Planned
**Context**: Finalization and settlement warnings are built as English strings in the application layer (`get_settle_up_data.py`, `record_waived_settlement.py`, `record_settlement.py`) — e.g. "Outstanding balance of $X in {year}", "No upload from {name}". Copy changes mean touching use cases and their unit tests, and money formatting there can't use the frontend's `formatCurrency`. Flagged in the v1.11.0 altitude review; deferred as an API-shape change beyond that diff (the amount formatting was patched in place).

- [ ] **Warnings as `{code, params}`**
    - Effort: M
    - What: Use cases return structured warnings (e.g. `missing_upload {person_id}`, `open_balance {amount, year}`, `premature_waive {person_id}`) through the API; the frontend maps codes to copy and formats params with `formatCurrency`/person names. All warning strings deleted from the application layer and their tests assert codes + params instead of English.
    - Why: Presentation belongs above the interface boundary; copy edits shouldn't require backend releases.
    - Dependencies: v1.11.0 (settle-up API shape)
    - Status: Not Started
    - Notes: Chat consumes warnings too (`tool_executor` summaries) — give it one shared code→copy map in Python or render codes verbatim in tool results; don't grow a second English composer.

### v1.16.2: Rewrite public history to the neutral examples
**Goal**: The public repository's full history matches the neutral examples the current files already use.
**Status**: Planned
**Context**: This is its own version because the force-push needs the maintainer's go-ahead, and no other release should wait on that approval.

- [ ] **Rewrite public history to the neutral examples**
    - Effort: S
    - What: Rewrite the git history so older commits match the current neutral examples (Alice and Bob, illustrative figures, generic consumer names) using `git-filter-repo`, then force-push `main`.
    - Why: The current files already use neutral examples, but older commits still contain the names, figures, and private-tool references they replaced, and a public repo exposes its whole history.
    - Dependencies: The maintainer's go-ahead before the force-push, which cannot be undone; `git-filter-repo` is installed only with the maintainer's approval.
    - Status: Not Started
    - Notes:
        - The step-by-step plan is in the maintainer's local handoff note in `docs/` (untracked, never committed).
        - After the force-push, ask GitHub to purge cached views, following its "Removing sensitive data from a repository" guide.
        - Acceptance:
            - The full history matches nothing on the maintainer's local denylist.
            - TruffleHog over the whole history is clean.
            - Tests pass at the rewritten `HEAD`.
            - Rewritten tags are pushed without triggering the release workflow: `.github/workflows/release.yml` runs on `v*` tag pushes, so the workflow is disabled during the push and re-enabled after.
            - GitHub's cached views are purged.
            - The local working copy is reset to the rewritten `main`.
