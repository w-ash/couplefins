# v1.8.0 — Agentic Chat Foundations

Status: Completed (2026-07-09)
Effort: M
Series overview: [v1.8.x — Agentic Chat](v1.8.x-agentic-chat.md)

## Goal

Prepare the chat assistant for capability parity and agentic work: current
model, a registry that makes the parity contract explicit and testable, and
tool descriptions tuned for how Opus 4.8 actually triggers tools. Invisible
to users — no new capabilities ship in this version.

## What shipped

### Model upgrade (Opus 4.8 + adaptive thinking)

- `ChatConfig` (`src/config/settings.py`): `model_id="claude-opus-4-8"`,
  `max_turns` 8→24, new `max_tokens: 16384` (replaces a hardcoded 8192 in the
  loop), new `effort: "high"`.
- Adapter (`src/infrastructure/chat/anthropic_adapter.py`): explicit
  `thinking={"type": "adaptive"}` (Opus 4.8 runs WITHOUT thinking when the
  parameter is omitted), typed `output_config={"effort": ...}` replacing the
  `extra_body` hack, `effort` threaded through `LLMClientProtocol.stream()`
  and `ChatCommand` so future callers (the v1.8.3 subagent) can run cheaper.

### Critical fix: content-block round-trip

`_content_block_to_dict` previously collapsed any block that wasn't
text/tool_use to `{"type": block.type}` — with adaptive thinking on, that
corrupts thinking blocks (whose `signature` the API validates when the
assistant turn is echoed back in a tool loop), degrading or 400ing every
multi-turn chat. Now serializes all block types via
`model_dump(mode="json", exclude_none=True)`; pinned by
`tests/unit/infrastructure/test_anthropic_adapter.py` and verified against
the live API (thinking + tool_use turn echoed back, second turn clean).

### Tool registry + human-only blacklist

`src/application/chat/registry.py` is the single source of truth for the
chat capability surface:

- `ToolSpec(name, kind, handler, use_cases, executor?, broadcast_entity?)` —
  the API tool list (`TOOLS`, cache breakpoint on the last entry), tool
  dispatch (`execute_tool`), and confirmation dispatch
  (`execute_confirmed_action`) all derive from `REGISTRY`.
- Explicit classification constants: `BLACKLISTED_USE_CASES` (all auth,
  `SetupCoupleUseCase`, `UpdatePersonUseCase` — human-only by product
  decision), `MECHANICALLY_EXCLUDED_USE_CASES` (CSV file I/O),
  `INTERNAL_USE_CASES` (seeders, prompt-context queries),
  `PENDING_PARITY_USE_CASES` (scheduled for v1.8.1/v1.8.2).
- **Parity contract test**
  (`tests/unit/application/chat/test_registry_parity.py`): walks
  `src/application/use_cases/` and fails if any use case is not in exactly
  one bucket, if buckets overlap, if names go stale, or if a blacklisted use
  case becomes chat-reachable. Adding a feature and forgetting the chatbot is
  a CI failure.
- `tool_executor.py` keeps handlers (now public `handle_*`),
  `confirmed_actions.py` keeps executors (uniform
  `(action, current_user)` signature); neither owns dispatch anymore.

### Description overhaul (Opus 4.8 tuning)

Opus 4.8 under-reaches for tools whose descriptions only say what they do.
Every tool description in `tools.py` now leads with a trigger sentence
("Call this when the user asks who owes whom…"), and the system prompt
gained `<tool_habits>`: always look up rather than answer from memory, chain
tools freely, propose mutations directly instead of describing them, assume
sensible defaults (current month, household scope) and state assumptions.
Voice files (fiona/standard) reviewed and intentionally left unchanged —
they are character definitions, not Sonnet-era tone scaffolding.
