### v1.1.0: Transaction Notes, Discuss Elevation & UI Polish
**Goal**: Surface imported Monarch notes in the UI, make them editable, elevate the "discuss" tag into a scannable workflow, normalize tags to case-insensitive, and polish the transaction editing and table layout.
**Status**: Completed (2026-03-31)
**Context**: The Monarch CSV `Notes` column was already imported and stored (`notes: str` on Transaction, `notes` column in DB), but invisible in the UI — searchable only. Couples use a "discuss" tag in Monarch to flag transactions for their together session, but it was buried in the tag list. Tags from Monarch preserved original casing (e.g., `"Discuss"`) causing case-sensitive comparison bugs. The transaction editor used a 4-way type selector (Personal/Shared/Spotted/Household) that obscured the actual two-dimension model (household/personal + split percentage).
**What this unlocks**: Visible transaction context from Monarch, editable notes for solo-prep annotations, a scannable "needs discussion" workflow with filter chips, case-insensitive tag handling throughout, and a clearer transaction editor reflecting the two-dimension model.

#### Backend: Case-Insensitive Tags

- [x] **Normalize tags to lowercase throughout**
    - Effort: S
    - Dependencies: v1.0.4
    - Status: Completed (2026-03-31)
    - What: Tags from Monarch were stored with original casing (e.g., `"Discuss"`, `"Shared"`), causing case-sensitive comparison bugs.
