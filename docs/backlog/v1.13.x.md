# v1.13.x: Insights Redesign — Where the Money Went

For strategic overview, see the [planning overview](README.md).

## Why this version

The Insights page grew by accretion: three hand-rolled KPI cards, a grid of
comparison cards, twelve sparkline cards, and a "Who's paying" section with
two more charts. It answered "how did each group trend?" but not "where did
the money go?", it needed a long scroll, and its only deep link dropped the
category group. A survey of 2026 finance apps (Monarch's Cash Flow Sankey
and Reports donut, Actual Budget's Sankey folding rules, Copilot's stacked
monthly bars with a prior-period overlay, Apple Card's one-sentence
comparison) set the pattern: all view state in the URL, every chart element
a link to the transactions behind it, a legend that is a table, and a hard
cap on how many nodes or slices are drawn before the long tail folds into
"Everything else".

This series rebuilds the page around one dataset — spending flow cells of
(source, group, category) — served precomputed by the same lens Budget and
the Dashboard use, and makes every figure on the page open the Transactions
list that sums to it.

### v1.13.0: Transactions personal scope matches the share rule
**Goal**: A personal-scope deep link from Insights or the Dashboard lands on a list whose total equals the figure it came from.
**Status**: Completed (2026-09-05)
**Context**: Transactions' `personal` scope listed non-household rows only (`isInPersonalScope` short-circuited on `household`; `fetch_scoped_rows` did the same server-side), so "My Spending" drill-downs under-counted. Tracked as a v1.12.0 post-deploy revision.

- [x] **Personal = every row where my share is positive**
    - Effort: M
    - What: `fetch_scoped_rows` (server) and `isInPersonalScope` (web) both use the viewer's share: household splits included, partner-paid rows where the viewer owes part, and what the partner spotted for them; a row where the share is $0 is not theirs. The Transactions "In view" card sums the viewer's shares in personal scope (`sumMyShares`) and says so. The chat `search_transactions` tool follows the same rule.
    - Why: Insights, Dashboard, and Transactions now agree on what "my spending" is, to the cent.
    - Dependencies: None
    - Status: Completed (2026-09-05)

### v1.13.1: Spending flow dataset and one Transactions link builder
**Goal**: The insights endpoint serves everything the redesigned page draws, precomputed, and every cross-page link into Transactions is built one way.
**Status**: Completed (2026-09-05)
**Context**: The page needed per-period (source → group → category) sums, top merchants, largest rows, and category-level swings. `SettleUpAuditTable`, `SparklineCard`, Dashboard, and Upload each built Transactions URLs by hand, and only one of them knew how to expand a group into `cat=` names.

- [x] **`compute_spending_flow` and `compute_category_comparisons` in the domain**
    - Effort: M
    - What: `SpendingLens.flow_source(tx)` names where a row's money came from: the payer under full-amount lenses; `household_share` / `personal` / `spotted_for_me` under a person's lens. `compute_spending_flow` accumulates `(source, category)` cells for a set of months (the selected month, or January through it), plus top merchants (dominant category attached, refund-only merchants dropped) and the largest rows under the lens. `compute_category_comparisons` mirrors the group comparison cards at category grain. Parity tests pin that flow cells sum to `total_spending` and to the YTD group summaries under every lens.
    - Why: One accumulator, one lens, additive cells the page can slice any way without arithmetic of its own.
    - Dependencies: None
    - Status: Completed (2026-09-05)

- [x] **Response reshaped around the flow**
    - Effort: S
    - What: `SpendingTrendsResponse` gains `month_flow`, `ytd_flow`, and `category_comparisons`; drops `budget_lines`, `settlement_trend`, `monthly_person_paid`, and the per-month `categories` list (flow cells replace it). The use case no longer loads the ledger or budgets. Orval regenerated; Recharts upgraded to 3.10.1 for Sankey click handlers and custom node/link renderers. The chat `get_spending_trends` tool also reports the year's top merchants.
    - Why: The page reads one payload; the removed fields had no reader left.
    - Dependencies: `compute_spending_flow`
    - Status: Completed (2026-09-05)

- [x] **`buildTransactionsUrl` in `web/src/lib/transaction-links.ts`**
    - Effort: S
    - What: One builder takes a month or an explicit date range plus scope, payer, category names, a merchant query, and the settlement flag, in a stable param order. Settle Up, Dashboard, Upload, and Insights all use it.
    - Why: A group deep link expands to its exact `cat=` names everywhere, and a year-to-date link carries `startDate`/`endDate`.
    - Dependencies: None
    - Status: Completed (2026-09-05)

### v1.13.2: Insights page redesign
**Goal**: A compact page that answers "where did the money go?" with a Sankey, a donut, and proportional bars; shows spending over time; calls out what moved; and links every figure to its transactions.
**Status**: Completed (2026-09-05)
**Context**: See "Why this version". Design decisions from the research: the Sankey's left column is who paid (household) or the viewer's sources (My Spending); per group the top four categories or any over 3% stay and the rest fold into "Everything else (n)"; donuts and bars cap at eight slices; the legend is a table that drills and links; the monthly chart stacks groups with the prior year as a dotted line; the budget overlay and the "Who's paying" section are gone (Budget and Settle Up own them).

- [x] **View state in the URL**
    - Effort: S
    - What: `useInsightsFilters()` — `scope`, `period=month|ytd`, `chart=flow|donut|bars`, `by=group|category|merchant` — beside the existing `year`/`month`. Budget uses `view=monthly|ytd`; Insights uses `period` because the chart type is a separate axis.
    - Why: Shareable views; Back restores the same page (the Monarch pattern).
    - Dependencies: None
    - Status: Completed (2026-09-05)

- [x] **Pure data modules**
    - Effort: M
    - What: `spending-flow.ts` (stable group colors, source labels, Sankey nodes/links with folding, slice builders with an "Everything else" fold) and `insights-data.ts` (headline with a comparison sentence, monthly stack, group rows with deltas and categories, the notable list with the creep detector). All unit-tested against a shared fixture in `web/src/test/insights-fixtures.ts`.
    - Why: Charts stay thin; the arithmetic that remains on the client is additive and tested.
    - Dependencies: v1.13.1
    - Status: Completed (2026-09-05)

- [x] **Components and page**
    - Effort: L
    - What: `web/src/components/insights/` — `SpendingFlowChart` (Recharts Sankey, 12 px nodes, source→target gradient links at 0.3 opacity, two-line labels, node and link clicks navigate), `SpendingDonut` (center total, slice click drills or navigates), `SpendingBars`, `SpendingLegendTable` (breadcrumb drill, "Everything else" expander, links), `MonthlyStackChart` (click a bar to select the month), `GroupBreakdownTable` with `MiniTrendLine`, `NotableList`. `StatsGrid` gains `accent` and `href`. `InsightsPage` is headline strip → Where the money went → Spending over time → Notable. `SparklineCard`, `ComparisonCard`, `PersonPaidChart`, `SettlementTrendChart` deleted.
    - Why: Less scroll, more answers, every figure a link.
    - Dependencies: Pure data modules
    - Status: Completed (2026-09-05)
    - Notes: Sankey and donut cannot draw a refund-heavy cell; the flow leaves it out with a footnote and the group table still counts it. Below 640 px the Sankey scrolls horizontally rather than re-flowing.
