# v1.8.4 — Chat Hardening: UserData Boundaries + Review Fixes

Status: Completed (2026-07-15)
Effort: S
Depends on: v1.8.3 (the surfaces being hardened)
Series overview: [v1.8.x — Agentic Chat](v1.8.x-agentic-chat.md)

## Goal

Post-review hardening pass over the v1.8.0–v1.8.3 chat stack. Centralize the
`<user_data>` prompt-injection labeling convention into one module with
explicit boundaries (instead of inline f-string wrapping scattered across
handlers and strip sites scattered across the frontend), fix the correctness
gaps review found, and consolidate duplicated resolution/validation logic.

## Part 1 — `user_data.py`: one marker, three boundaries

- [x] **UserData marker module** — `src/application/chat/user_data.py`.
  Handlers mark user-originated strings (merchants, categories, tags, notes,
  filenames, settlement-merchant names/patterns) with `UserData`, a `str`
  subclass carrying the RAW value; nothing is wrapped at construction time,
  so one summary dict safely feeds every consumer.
  Status: Completed (2026-07-15)
  - **Model boundary (wrap)**: `wrap_for_model` runs where tool results are
    serialized into model context — the tool-result loop in `use_case.py` and
    the confirm-context injection in `routes/chat.py`. Non-mutating rebuild:
    the pending-confirmation `details` dict stays raw in the
    PendingActionStore.
  - **Frontend boundary (strip)**: ToolResultEvent summaries pass through
    `strip_user_data` before the SSE stream — the frontend renders raw values
    and its per-card `stripUserData` call sites are deleted. Only assistant
    *prose* is still stripped client-side (`ChatMessage`), because the model
    can echo tags into its text.
  - **Input boundary (sanitize)**: `registry.execute_tool` (the single
    dispatch point) strips tags from every incoming tool_input, so wrapped
    values the model echoes back can never break lookups or persist. System
    and subagent prompts updated: passing tags in tool inputs is now
    harmless; strip them only when quoting.
- [x] **Breakout hardening** — `wrap()` removes embedded `</user_data>` tag
  literals before wrapping, so a malicious merchant name cannot escape its
  data context. Errors that embed DB-sourced values and reach the model via
  `str(e)` (already-linked/not-linked settlement transactions, existing
  settlement merchants, confirmation descriptions) now wrap those values.
  Status: Completed (2026-07-15)
- [x] **Dead duplication removed** — `confirmed_actions._strip_user_data`
  deleted (details are raw now); settlement-merchant `raw_name`/`raw_pattern`
  shadow fields collapsed into `name`/`pattern`.
  Status: Completed (2026-07-15)

## Part 2 — Tool kind over SSE

- [x] `tool_start` frames carry `kind` (`read`/`write`/`agentic`) resolved
  from the registry, and the frontend renders "Looking up… vs Proposing…"
  from it. The name-prefix heuristic (`isMutationTool` + its
  `delegate_analysis` override set) is deleted — the registry is the single
  source of truth. `ToolCall.kind` is optional client-side for frames from
  older streams (defaults to `read`).
  Status: Completed (2026-07-15)

## Part 3 — Correctness fixes

- [x] **Bulk-update finalization gap** — the finalization check on
  `bulk_update_transactions` inspected only the *first* transaction's month;
  a batch spanning months could mutate a finalized month. New
  `_assert_months_open` batch-checks every affected month via
  `get_by_periods` and names each finalized month in the error.
  Status: Completed (2026-07-15)
- [x] **Input validation gaps** — `get_settlement_balance` rejects year
  without month (and vice versa); `bulk_update_transactions` validates
  `payer_percentage` through the domain's `check_payer_percentage`;
  `record_settlement` reuses the shared command validators
  (`assert_positive_decimal`, `assert_month_annotation_pair`) instead of
  local re-implementations.
  Status: Completed (2026-07-15)
- [x] **`code_start` command fallback** — the SSE frame read only the
  `code` input key; bash-style server-tool inputs use `command`. Falls back
  `code` → `command` → empty.
  Status: Completed (2026-07-15)

## Part 4 — DRY consolidation + streaming perf

- [x] Category-group resolution collapsed to one path:
  `_find_group_in`/`_require_group_in` (pure, over a loaded list) +
  `_require_group` (loading wrapper) with the actionable "Valid groups: …"
  error everywhere — replaces `_resolve_category_group_id` and two inline
  lookups. `_fetch_transactions` centralizes bulk ID resolution with a
  missing-IDs error. Repeated year/month schema properties in `tools.py`
  extracted to `_YEAR_PROP`/`_MONTH_PROP`.
  Status: Completed (2026-07-15)
- [x] `ChatMessage` memoized — the store's `updateMessage` preserves
  identity of untouched messages, so streaming one message no longer
  re-renders the whole list.
  Status: Completed (2026-07-15)

- Full backend + frontend quality gates green.
