# v1.9.4 — MCP + Routing Review Hardening

Status: Completed (2026-07-17)
Effort: S
Depends on: v1.9.3 (MCP server), v1.9.0 (page routing)
Series overview: [v1.9.x — Context Engineering](v1.9.x-context-engineering.md)

## Goal

Post-release hardening of the v1.9.x series from a multi-agent code review
(10 finder angles → adversarial verification → gap sweep, 15 findings).
Same posture as v1.8.4: fix every confirmed defect, encode each guarantee
in a named test, document the one deliberate skip.

## What shipped

### Confirmation protocol (`confirmation.py`, `pending_actions.py`)

- [x] **Token↔tool binding in the store** — `PendingActionStore.claim`
  gains an optional `tool_name`; the check runs BEFORE deletion, so a token
  minted by tool A's preview can neither commit through tool B (when the
  argument dicts coincide) nor be destroyed by the mistaken cross-tool
  call — A's preview stays pending and confirmable. The chat route's
  claim (no tool_name) is unchanged.
- [x] **Explicit `confirm: null` previews** — schema-driven clients that
  serialize every declared optional as null were hard-erroring on all 16
  write tools; null now means "omitted" (the truthy-string rejection stays).
- [x] **Null-tolerant drift comparison** — explicit JSON nulls for optionals
  omitted at preview are no longer rejected as drift (both sides normalized
  by dropping None-valued keys). Safe by construction: the commit executes
  the stored propose-time input, never the confirm-time args. Added-default
  drift (a value appearing only at confirm) stays a rejection — strictness
  is the feature; the error message self-corrects in one re-preview cycle.
- [x] **Shared field constants** — `CONFIRM_FIELD`/`CONFIRM_TOKEN_FIELD`
  declared once in `confirmation.py`, consumed by `server.py`'s schema
  injection; plus an import-time guard rejecting any future write tool that
  declares the reserved names (it would work in chat and silently break
  over MCP).

### Entrypoint + identity (`__main__.py`, `server.py`)

- [x] **`install <client> <person>` order accepted** — the client-first form
  silently discarded the person positional and embedded whatever
  `COUPLEFINS_MCP_PERSON` held (wrong-identity registration in a two-person
  ledger). Both positional orders now work; env read consolidated into
  `_person_from_env()`.
- [x] **Unknown subcommand errors** — a typo (`instal`) fell through to the
  stdio server and blocked forever on stdin; now usage error, exit 2.
- [x] **`_PersonsCache` concurrency + emptiness** — the SDK dispatches each
  request in its own task: a stale-TTL burst now collapses into one Neon
  fetch (double-checked `anyio.Lock`), and an empty pre-setup persons list
  is never cached, so completing couple setup lands immediately instead of
  after a full TTL.
- [x] **`tools/list` precomputed** — the registry is immutable per process;
  the wire-format `Tool` list is built once at import.

### Chat surface

- [x] **`page` degrades, never rejects** — `max_length=64` 422'd the whole
  chat message over an advisory hint; overlong values now validate to None
  (same behavior as any unknown page).
- [x] **`pageSection` case-insensitive** — React Router matches routes
  case-insensitively, so `/Budget` rendered but silently dropped the page
  signal; the segment is now lowercased.
- [x] **`SECTION_BY_SEGMENT` derived** — from `navigation.ts`
  PRIMARY/SECONDARY routes instead of a third hand-synced literal map.

### Consistency + DRY

- [x] `build_system_prompt` voice fallback via `VOICE_NAMES` membership
  (was: call `get_voice` to probe for ValueError, discard, resolve again).
- [x] `_SUBAGENT_HOT_TOOLS` validated at import like `_PAGE_TOOL_HINTS`
  (unknown/non-read names fail the import, not just a parity test).
- [x] Canonical `ALICE`/`BOB` fixtures promoted to
  `tests/fixtures/factories.py` (were triplicated); `settle_args()` shared
  via the MCP conftest.

## Deliberately not fixed (documented decision)

**Consumed-vs-expired token indistinguishability**: after a successful
commit whose response is lost, retrying the identical confirm re-previews
with a fresh token — an auto-confirming client could commit twice. The
store deletes claimed actions (no tombstone), and re-preview-on-expired is
the live-verified v1.9.3 contract. A fix needs consumed-token tombstones
and a deliberate contract change — candidate for a future version, not a
review patch. Refuted during verification: the subagent tool list's
deferred-before-breakpoint layout (deferred discovery preserves the cache;
append semantics per the v1.8.3 verification notes).

## Acceptance

- Cross-tool confirm rejected AND the original preview still commits.
- `confirm: null` / null-valued optionals preview and commit cleanly.
- `install cursor Alice` embeds Alice regardless of the env var.
