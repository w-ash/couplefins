### v1.2.0: Scoped Dashboard
**Goal**: Add household/personal/all scope toggle to the Dashboard, with self-documenting metrics that always explain what's included, the time period, and why the number is useful.
**Status**: In Progress
**Context**: The dashboard was household-only with no scope awareness. Budget and Transactions pages already had scope toggles. Each scope changes the dashboard's purpose: household = "how are we doing together?" (settlement-oriented), personal = "how am I doing?" (spending-health-oriented), all = "what's the full picture?" (observational). Metric labels like "This month" were ambiguous — unclear whether they included personal spending, household-no-split transactions, or just settlements. Progressive disclosure research confirmed every metric needs a contextual description layer.
**What this unlocks**: The dashboard becomes scope-aware and self-documenting. Personal scope surfaces budget alerts and per-person spending. All scope shows total financial footprint. Every stat card has a description explaining exactly what it includes.

### v1.2.1: "Shared" → "Household" Terminology Cleanup
**Goal**: Replace "shared" as a domain concept with "household" throughout the codebase. "Shared" should only refer to the Monarch CSV tag name.
**Status**: Completed (2026-04-01)
**Context**: The codebase evolved from a "shared expense" mental model to a two-dimension model (`household` flag + `payer_percentage`). The v0.9.0 refactor introduced the `household` field but left "shared" in domain entities, API schemas, variable names, and UI labels. The `TransactionType` enum (`shared/spotted/household/personal`) is a vestige of the old model — it maps combinations of the two orthogonal fields into named types, but the two fields ARE the model. "Shared" is not a type — it's just `household=true` with a non-100% split.
**What this unlocks**: Terminology matches the actual data model. No more confusion about whether "shared spending" means "split transactions" or "all household expenses."
