# v1.9.0 — Page-Contextual Tool Routing

Status: Completed (2026-07-16)
Effort: M
Depends on: v1.8.3 (defer_loading + tool search), v1.8.4 (SSE tool kinds)
Series overview: [v1.9.x — Context Engineering](v1.9.x-context-engineering.md)

## Goal

The frontend reports which UI section the user is on; the server promotes
that section's deferred read tools into the loaded set. A user on the Budget
page asking "how are we doing?" gets `get_budgets` loaded directly instead
of paying a tool-search hop — while the cached tool prefix stays
byte-identical across navigation, so the promotion is cache-free.

Also fixes a latent defect: `build_tools()` stamps `cache_control` on the
last non-deferred REGISTRY entry, which is `tool_search_tool_bm25` — a raw
`{type, name}` server block. mixd's architecture doc flags exactly this
placement as invalid (server blocks reject `cache_control`); either the API
tolerates it or tool-list caching has been silently degraded. The tier
restructure moves the breakpoint onto `delegate_analysis`, the last
*dispatched* prefix tool. Verify live with `usage.cache_read_input_tokens`
before/after and record the verdict here.

## Design

Three tiers, in order, cribbed from mixd `registry.py` `build_tools`:

1. **Prefix** (page-invariant, cached): every non-deferred dispatched tool —
   the 3 hot reads (`get_settlement_balance`, `get_budget_overview`,
   `search_transactions`) + `delegate_analysis`. Breakpoint on the last
   entry.
2. **Promoted** (per-page, cached separately): the page's hinted tools,
   emitted *without* `defer_loading`, second breakpoint on the last entry.
   Empty (and unstamped) when no page / unknown page.
3. **Rest** (uncached): raw server blocks (`code_execution` when enabled,
   `tool_search_tool_bm25`) + the remaining deferred pool with
   `defer_loading: True`.

Page → hints map (deferred reads only; promotion ceiling derived:
10-tool loaded budget − 6 always-loaded = 4/page):

| Page | Promoted tools |
|---|---|
| dashboard | get_dashboard_summary, get_dashboard_status |
| transactions | get_transaction_history, get_tags |
| settle | get_settlement_activity, get_adjustments_preview |
| budget | get_budgets, get_spending_by_group |
| insights | get_spending_trends, get_spending_by_group |
| upload | get_upload_history, get_reconciliation_report |
| settings | get_category_setup, get_tags |

No page / unknown page / the mobile full-screen chat page (`/ask`) /
`/account` → promote nothing; the hot core + tool search posture is
correct there. Tools may appear on multiple pages.

## Acceptance

- Cached tool prefix byte-identical for every page value including None.
- Loaded (non-deferred) tool count ≤10 on every page.
- Exactly one tools breakpoint pageless, exactly two on a promoting page,
  and every breakpoint sits on a dispatched tool schema.
- Full quality gate green.
